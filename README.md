# Practical lesson: pz-UML

## Предметна область: Система бронювання готелю

## 1. Use Case Diagram

```mermaid
graph TD
    Client([Клієнт])
    Admin([Адміністратор])
    Client --> UC1[Переглянути номери]
    Client --> UC2[Зробити бронювання]
    Client --> UC3[Скасувати бронювання]
    Admin --> UC5[Керувати номерами]
    Admin --> UC6[Переглянути бронювання]
    Admin --> UC7[Підтвердити бронювання]
```

## 2. Sequence Diagram

```mermaid
sequenceDiagram
    participant C as Клієнт
    participant S as Система
    participant DB as База даних
    C->>S: Обрати номер та дати
    S->>DB: Перевірити доступність
    DB-->>S: Номер доступний
    S-->>C: Показати деталі
    C->>S: Підтвердити бронювання
    S->>DB: Зберегти бронювання
    S-->>C: Бронювання успішне
```

## 3. Activity Diagram

```mermaid
flowchart TD
    A([Початок]) --> B[Обрати дати]
    B --> C{Є номери?}
    C -- Ні --> D([Кінець])
    C -- Так --> E[Обрати номер]
    E --> F[Оплата]
    F --> G{Успішно?}
    G -- Ні --> F
    G -- Так --> H[Зберегти бронювання]
    H --> I([Кінець])
```

## Опис діаграм

- **Use Case** - взаємодія Клієнта та Адміністратора з системою
- **Sequence** - послідовність повідомлень при бронюванні
- **Activity** - потік дій від вибору дат до підтвердження
